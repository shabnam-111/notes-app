# Features added after v1

## Pinned notes
- Pin/unpin from the pin icon on a card, on the note page, or the "Pin this note" checkbox in the editor.
- Pinned notes get their own **Pinned** section above **Others**; within each, newest edit first.
- API: `pinned` (boolean) on `POST /api/notes` and `PUT /api/notes/<id>`; filter with `GET /api/notes?pinned=true`.

## Rich-text editor (Quill 2, vendored in `app/app/static/vendor/quill`, no CDN)
| You can | How |
|---|---|
| Text size 10-48 | Size dropdown (default 16) |
| Text colour / highlight | Colour pickers |
| Heading 1-3, bold, italic, underline, strike, lists, alignment, links | Toolbar |
| **Images** | Image button, drag-and-drop, or paste. PNG/JPEG/GIF/WebP up to 2 MB |
| **Shapes** | Shape button: rectangle, rounded rectangle, circle, triangle, diamond, star, arrow, line. Pick fill and outline colour (or "No fill") before inserting |
| Resize or remove an image or shape | Click it, then S / M / L / Full / Remove |

Recolouring an already-inserted shape is not supported - delete it and insert a new one.

## How it is kept safe
Rich text means HTML from users, so:
1. **Server-side allow-list** (`sanitize.py`, using `nh3`): fixed tag list; only `color`, `background-color` and `font-size`
   styles with validated values; only `ql-align-*`/`ql-indent-*` classes; `<img>` only if `src` is one of *our* image or shape URLs.
   No scripts, event handlers, iframes, `javascript:` links, `data:` URIs or remote images (no tracking pixels).
2. Sanitised **when saved and again when rendered**, so a tampered database row cannot inject script.
3. **Content-Security-Policy** (`script-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`) plus `nosniff`.
4. **Images**: the file's real bytes are checked (not its name or declared type); **SVG uploads are refused**; stored in the
   database; only the owner can fetch them; CSRF-protected upload; 200 images per account.
5. **Shapes** are generated by the server from a fixed list with colours validated as `RRGGBB`, and served with a sandboxing CSP.

## Why images live in the database
Pods run with a read-only filesystem and several replicas (and two colours under Blue-Green), so local files would be missing
on other pods. The database is already shared and backed by a PersistentVolume. For heavy use, move to object storage (S3/MinIO).

## Database changes and Blue-Green
New columns (`body_format`, `pinned`, `search_text`) and the `images` table are created automatically at start-up by
`app/app/schema.py`. They are additive with defaults, so the previous release keeps working after the upgrade - rollback stays safe.

## Known limits
- Deleting a note does not delete its images (orphans stay until a cleanup job is added).
- Tables and nested lists are not supported; indentation is limited to 8 levels.
- Two people editing the same note: the last save wins.
- The editor needs JavaScript; there is no plain-text fallback form.
